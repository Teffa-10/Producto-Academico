# 🌐 Blog Personal – Proyecto Web

## 🚩 Problema a Resolver

En la actualidad, enfrentamos desafíos tecnológicos con más frecuencia de la que quisiéramos. Ya seas un usuario individual o una empresa, los problemas de software están a la orden del día. Crear un **blog personal** nos permite explorar y enfrentar estos desafíos desde la práctica.

### 🛠️ Problemas Comunes Detectados

1. **🐌 Lentitud del sistema**  
   Solución: Limpieza regular, cierre de apps en segundo plano y escaneos de seguridad.

2. **⚠️ Conflictos de software**  
   Solución: Mantener drivers y software actualizados, restaurar versiones estables.

3. **🔄 Falta de compatibilidad**  
   Solución: Actualizar software o usar modos/máquinas virtuales compatibles.

4. **🔒 Fallos de seguridad**  
   Solución: Software actualizado, antivirus confiable y monitoreo constante.

5. **💾 Pérdida de datos**  
   Solución: Copias de seguridad frecuentes y uso de almacenamiento en la nube.

---

## 🚀 Propuesta de Solución

Desarrollar un **blog personal estático** usando solo **HTML y CSS**, para poner en práctica buenas técnicas de desarrollo web y gestión de proyectos colaborativos.

---

## 🧠 ¿Por qué usamos metodologías ágiles?

Las metodologías ágiles nos permiten:

- 🔁 **Adaptarnos a cambios** con rapidez.
- 📦 **Entregar avances continuos**, en vez de esperar al final.
- 📊 **Mejorar constantemente** gracias a reuniones de retroalimentación.
- 📣 **Comunicación efectiva** entre el equipo y stakeholders.
- 🎯 **Enfoque total en el usuario final**.
- 🛡️ **Menor riesgo de errores graves**.
- 💪 **Mayor motivación del equipo** gracias a la autonomía.

Usamos herramientas como **GitHub Projects (Kanban)** para organizar tareas, y ciclos iterativos para mejorar continuamente.

---

## 🧯 Manejo de Excepciones (HTML puro)

Aunque no usamos backend ni JavaScript, aplicamos medidas de prevención:

- 🔗 Validación manual de enlaces rotos (con herramientas del navegador o W3C).
- 📄 Página personalizada de error `404.html`.
- 🗂️ Verificación continua de estructura de carpetas y archivos.
- 🔁 Control de versiones con Git/GitHub (para revertir errores).

---

## ✨ Código Limpio y Buenas Prácticas

En un equipo de 4 personas, estas prácticas son clave:

- 📁 **Estructura clara**: `/pages`, `/assets/img`, `/styles`, etc.
- 🔤 **Nombres descriptivos** para archivos, etiquetas y clases.
- ✅ **Validación con W3C** para asegurar HTML semántico y sin errores.
- 🧹 **Refactorización continua**: sangría uniforme, limpieza de etiquetas, comentarios útiles.
- 🔍 **Revisión cruzada en GitHub**: trabajo con ramas + pull requests.
- 🧩 **Uso del tablero Kanban**: tareas divididas y asignadas para mejorar seguimiento y colaboración.
